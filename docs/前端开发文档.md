## 0. 一分钟速览

MusicMaster = 一体化音乐处理,四个互相独立的能力,一个 Gradio 单页 GUI 串起来:

| Tab | 能力 | 计算 | 后端入口 | 调用方式 |
|---|---|---|---|---|
| 🎼 互转 | 简谱 ⇄ 五线谱 双向无损 + 导入 | **CPU**,本进程 | `musicmaster.convert.convert` | 直接函数调用 |
| 🎤 扒谱 | 音频 → 五线谱 + 简谱 + 逐音可信度 | **CPU**,本进程 | `musicmaster.transcribe.autopilot` | 直接函数调用 |
| 🔊 分离 | 混音 → 人声/伴奏/去和声/降噪 | **GPU**,子进程 | `musicmaster.separate.pipeline` | **子进程** → 分离 venv |
| 🎚️ 修音换音色 | 跑调清唱 → 在调+干净+仍是你 | **GPU**,子进程 | `musicmaster.vocal.pipeline` | **子进程** → 修音/换音色 venv |

**关键事实**:GUI 跑在 CPU 主环境(`.venv`)。互转/扒谱与它同环境 → **直接 import 调用**;
分离/修音换音色是 GPU 重依赖、各有独立 venv → **子进程调用**(路径由配置文件/环境变量给)。
所以**互转 / 扒谱开箱即用**,分离 / 修音换音色需先装 GPU venv(见 §6)。

## 1. 运行 / 重启 / 端口

```bash
# 启动(三选一)
双击 start_gui.bat          # Windows 首选(纯 ASCII + CRLF)
python start_gui.py         # .bat 失败时的稳妥启动器(系统 Python 转交 .venv)
.venv\Scripts\python.exe app.py   # 直接跑

# 浏览器自动开 http://127.0.0.1:7860(被占用自动顺延 7861…)
```

- ⚠️ **改完后端代码必须重启 GUI**:Python 模块已加载进运行进程,不重启不生效。
- 端口:环境变量 `GRADIO_SERVER_PORT`(非数字会被忽略并自动选口)、`GRADIO_SERVER_NAME`(默认 `127.0.0.1`)。
- 首次启动约 20–40 秒(载入 TensorFlow)。关闭窗口 = 停服务。

## 2. GUI 结构(`app.py`)逐控件说明

单文件 Gradio `Blocks`,`build()` 返回 `demo`,`if __name__=="__main__"` 里 `build().launch(...)`。
每个 Tab = 几个输入控件 + 一个按钮 + 几个输出控件,按钮 `.click(handler, inputs=[...], outputs=[...])`。

> **改前端最重要的规则**:`handler` 的**返回值元组元素个数必须 == `outputs` 列表长度**,否则 Gradio 报错。
> 下表的「返回」列就是 outputs 顺序。

### 2.1 🎼 互转 Tab

| 控件 | 类型 | 说明(= GUI 里给用户看的 info) | 传给后端的值 |
|---|---|---|---|
| `cv_file` | File | 上传 `.jianpu`/`.musicxml`/`.mid`/`.abc` | 文件路径 |
| `cv_dir` | Radio | 方向:`简谱 → 五线谱(MusicXML)` / `五线谱 → 简谱` | 选中的字符串 |
| `cv_key` | Textbox | 主音(调号 1=哪个音);仅「转简谱」用,如 G;留空自动 | 字符串或 "" |

- **handler**:`do_convert(file, direction, key)` → 返回 `(结果文本, 五线谱SVG的HTML, 下载文件路径)`
- **outputs**:`[cv_out(Textbox), cv_svg(HTML), cv_dl(File)]`

### 2.2 🎤 扒谱 Tab

| 控件 | 类型 | 说明 | 传给后端的值 |
|---|---|---|---|
| `tr_audio` | Audio(filepath) | 上传清唱/单旋律音频 | 文件路径 |
| `tr_engine` | Radio **(label,value)** | 引擎,见 §3.1。**显示带括号解释,值是裸名** | `crepe` / `basic-pitch` / `bytedance` |
| `tr_key` | Textbox | 调(1=主音),如 C;留空自动定调 | 字符串或 "" |

- **handler**:`do_transcribe(audio, engine, key)` → `(报告Markdown, 五线谱SVG_HTML, 下载文件列表, None)`
- **outputs**:`[tr_report(Markdown), tr_svg(HTML), tr_dl(File multiple), gr.State()]`
  - 第 4 个 `gr.State()` 是占位输出(Gradio 要求 outputs 与返回数对齐),返回 `None`。

### 2.3 🔊 分离 Tab(GPU)

| 控件 | 类型 | 说明 | 传给后端的值 |
|---|---|---|---|
| `sp_audio` | Audio(filepath) | 上传混音 | 文件路径 |
| `sp_stages` | Textbox | 处理段:`1`=分离人声/伴奏 · `2`=去和声 · `3`=降噪;填子集如 `1,2,3` | 字符串 |
| `sp_denoise` | Radio **(label,value)** | 降噪方法,见 §3.2 | `dereverb` / `deecho` |

- **handler**:`do_separate(audio, stages, denoise)` → `(日志/结果文本, 各轨wav列表)`
- **outputs**:`[sp_out(Textbox), sp_dl(File multiple)]`
- 未配置分离 venv 时返回友好提示(不崩),GPU 不可用不影响 CPU 两页。

### 2.4 🎚️ 修音换音色 Tab(GPU)

⭐ **三个输入是产品核心设计,别退回两输入**(原因见 `合并开发日志.md` Entry #8):

| 控件 | 类型 | 说明 | 传给后端 |
|---|---|---|---|
| `vc_raw` | Audio | ① 原始清唱(跑调) | 决定**唱什么内容** |
| `vc_ref` | Audio | ② 去和声参考(取目标旋律)**必须去和声** | 决定**唱成什么调**(目标 f0) |
| `vc_self` | Audio | ③ 你自己的清唱(音色锚 ~10–30s) | 决定**听起来是谁**(音色) |
| `vc_csteps` | Slider 50–200/默认150 | 修音步数(扩散迭代;越大越精细越慢) | `correct_steps` |
| `vc_vsteps` | Slider 20–100/默认50 | 换音色步数(扩散迭代;越大质量越高越慢) | `voice_steps` |
| `vc_cfg` | Slider 0–1/默认0.7 | **人声近似度(cfg 引导强度)**,见 §3.3 | `voice_cfg` |

- **handler**:`do_vocal(raw, ref, self_ref, correct_steps, voice_steps, voice_cfg)` → `(结果文本, 成品音频, 中间产物音频)`
- **outputs**:`[vc_out(Textbox), vc_final(Audio), vc_mid(Audio)]`
- ①② 要**同段、时间对齐**;②**必须去和声**(可先在「分离」页对原曲跑出 `clean`/`lead` 当 ②)。
- 整首会**自动分块出完整长度**(不截断),但**时长×步数越大越慢**(整首×150 步在 8GB 上约 20+ 分钟)。

## 3. 模型 / 参数怎么选(讲给用户的版本)

> 这是老板特别要求的部分:专业名词保留,但要让用户知道**区别**与**何时选哪个**。
> GUI 里每个控件已有括号 + 灰字 `info=` 简版;这里是完整版,前端可做成「帮助」弹层。

### 3.1 扒谱引擎(`tr_engine`)

| 引擎 | 中文定位 | 适合素材 | 出简谱? | 依赖 | 坑 |
|---|---|---|---|---|---|
| **crepe**(默认) | 单旋律深度学习音高跟踪(CREPE/torchcrepe) | 人声清唱、哼唱、单线条乐器 | ✅ 出简谱 + 逐音可信度 | TF 2.15 | 复音(和弦)会丢音 |
| **basic-pitch** | Spotify 通用复音音符检测 | 多音/和弦/乐器、兜底 | ❌ 仅五线谱 | TF 2.15(干净环境) | 噪声下人声主旋律会崩到~12%,**人声别用它** |
| **bytedance** | ByteDance 钢琴专用高分辨率(SOTA) | 干净 44.1k **真钢琴**录音 | ❌ 仅五线谱 | torch + GPU + 首次下权重 | 低质/非钢琴是 OOD,**会幻觉假和弦**(8kHz 实测吐 98 音) |

**一句话给用户**:唱的 / 哼的 / 单旋律 → `crepe`;多个音同时响(和弦/伴奏) → `basic-pitch`;纯钢琴干净录音 → `bytedance`。
**选错不会崩**(已加兜底 + L1 质量门会拦烂输入 + 报告里给提示),但结果会差。

> 三层质量护栏(扒谱独有):**L1 入口质量门**(扒之前先体检录音,烂输入门口拦+给修法)→
> 选引擎转录 → **L3 逐音可信度**(成串调外/双算法分歧 → 标「存疑段」,只让用户核对那几处)。
> 报告(`报告.md`)就是这三层的人话汇总。

### 3.2 分离降噪方法(`sp_denoise`,第 3 段用)

| 方法 | 作用 | 何时用 |
|---|---|---|
| **dereverb**(默认) | 去混响(房间残响),取「No Reverb」干声轨 | 默认;音量稳、不闷,适合大多数 |
| **deecho** | 去回声(重复回声),取「No Echo」轨 | 录音有明显回声/复读感时 |

> 三段级联:① BS-RoFormer 分离人声/伴奏 → ② Karaoke RoFormer 去和声(去 backing vocals)→ ③ 降噪提纯。
> 普通分离只到 ①;**「去 backing vocals」靠 ②**;③ 才是这里的 dereverb/deecho。

### 3.3 步数 与 人声近似度(修音换音色)

| 参数 | 是什么 | 越大 | 默认 | 给用户的话 |
|---|---|---|---|---|
| **修音步数** | DiffPitcher 扩散迭代次数 | 音准修得越精细,但越慢 | 150 | 想快可降到 50 |
| **换音色步数** | Seed-VC 扩散迭代次数 | 音质越细腻,但越慢 | 50 | 25 也能用 |
| **人声近似度(cfg)** | Seed-VC 分类器自由引导强度 | 越强调「贴目标音色」的条件 | 0.7 | **效果较细微**;设 0 约快 1.5× |

> ⚠️ **诚实告知(写进文档以免误导用户)**:本管线用 Seed-VC **V1** 模型,其 `inference-cfg-rate`
> 据官方 README 是「subtle(细微)」级旋钮。真正强力的「相似度」旋钮(`similarity-cfg-rate`)
> 只在 **V2** 模型才有,本项目**未上 V2**。
> **想更像本人**:优先用更干净/更长的 ③ 音色锚 + 适当加大「换音色步数」,效果比拉 cfg 明显。

## 4. 后端契约(换前端时照这个调,不必碰后端)

前端只是壳。要换成 React / 桌面应用 / REST API,按下面四个契约调即可。

### 4.1 互转(直接函数,CPU)
```python
from musicmaster.convert import convert as cv
score = cv.load_any("in.jianpu")          # → music21.Score(支持 .jianpu/.jp/.txt/.musicxml/.xml/.mxl/.mid/.midi/.abc)
                                          #   未知扩展/空/畸形 → 抛 ValueError/FileNotFoundError(友好,前端 try 转提示)
score.write("musicxml", fp="out.musicxml")           # 简谱 → 五线谱
text = cv.score_to_jianpu(score, key_name="G")       # 五线谱 → 简谱文本(key_name 留 None 自动;非法调名回退 C 不崩)
# 渲染五线谱预览(注意 core.__init__ 同名陷阱,见 §7):
from musicmaster.core.render import render            # ← 直接从子模块 import 函数本身
res = render("out.musicxml", "out_dir", formats=("staff",))   # → {"staff": "out_dir/staff.svg", ...}
```

### 4.2 扒谱(直接函数,CPU)
```python
from musicmaster.transcribe import autopilot
rc = autopilot.main(["in.wav", "--out", "out_dir", "--engine", "crepe", "--key", "C"])  # --key 可省(自动定调)
# 产物(out_dir/):报告.md、notes.json、out.mid、out.musicxml、staff.svg、jianpu.pdf(或 jianpu.ly)、confidence.json
# rc=0 成功;rc=1 引擎失败(报告.md 仍会写出,内含友好错误)。绝不抛裸 traceback。
```

### 4.3 分离(子进程,GPU)
```python
# 必须用「分离 venv」的 python 跑,它才有 audio-separator + CUDA torch
[sep_python, "-m", "musicmaster.separate.pipeline", "mix.wav",
 "--stages", "1,2,3", "--denoise", "dereverb", "--out-dir", "out_dir"]
# returncode: 0 成功(产物 wav 在 out_dir);2 = 某段失败(stderr 有人话原因,不会假成功)
```

### 4.4 修音换音色(直接函数,内部再起 GPU 子进程)
```python
from musicmaster.vocal import config as vcfg, pipeline as vpipe
probs = vcfg.check_paths("correct") + vcfg.check_paths("voice")   # 空列表=环境就绪;否则是缺失项人话提示
res = vpipe.two_stage(raw, ref, self_ref, "out_dir",
                      correct_steps=150, voice_steps=50, voice_cfg=0.7)  # shift 默认 -12
# → {"corrected_24k": Path, "corrected_44k": Path, "final": Path|None}
#   final 为 None = 修音成功但换音色没产出成品(前端别报 ✅,提示查 .venv-svc/权重)
```

## 5. 错误如何呈现到 UI(前端可依赖的约定)

经本轮鲁棒性加固(Entry #12),后端遵循:
- **CPU 两页**:handler 内 `try/except` 把异常转成 `❌ ...:<类型>: <消息>` 文本返回,**不崩页**。
- **扒谱**:任何阶段失败都仍写出 `报告.md`(失败信息在里面);缺引擎依赖给「改用 crepe / 装 X」提示。
- **分离**:子进程 returncode≠0 → 显示日志尾部;某段没产出 → 明确报哪段失败,**不会假成功**。
- **修音换音色**:环境未就绪先 `check_paths` 拦截给提示;成品为 None 给警示而非 ✅。
- **编码**:所有入口防御式 `sys.stdout/stderr.reconfigure("utf-8")`,GBK/英文代码页/重定向都不再 `UnicodeEncodeError`。

前端新壳建议沿用:**永远把后端异常 catch 成结构化提示**,别让原始 traceback 进 UI。

## 6. 环境 / venv / 配置(前端起服务前必读)

四类重依赖互相冲突,**分 4 个 venv**(`架构流程图.md` §6 有图):

| venv | 跑什么 | 关键依赖 |
|---|---|---|
| `.venv`(CPU) | **GUI + 互转 + 扒谱 + 渲染** | gradio==6.15.2 / music21 / librosa / crepe(TF2.15) / basic-pitch / verovio / jianpu-ly |
| `.venv-sep`(GPU) | 分离 | audio-separator + cu124 torch |
| `.venv-neural`(GPU) | 修音准(DiffPitcher) | torchcrepe/diffusers/pyworld/fastdtw + cu124 torch |
| `.venv-svc`(GPU) | 换音色(Seed-VC) | Seed-VC 锁定版(torch==2.4 等) |

**装环境**:`python scripts/setup_core.py`(主) / `setup_sep.py` / `setup_vocal.py`(GPU)。

**GPU 路径配置**(GUI 子进程靠它找 venv/源码)——优先级:**环境变量 > `paths.local.json` > 默认**:

| 环境变量 | `paths.local.json` 键 | 指向 |
|---|---|---|
| `MUSICMASTER_SEP_PYTHON` | `sep_python` | 分离 venv 的 python.exe |
| `MUSICMASTER_DIFFPITCHER_DIR` | `diffpitcher_dir` | DiffPitcher 源码目录 |
| `MUSICMASTER_VOCAL_PYTHON` | `vocal_python` | .venv-neural 的 python.exe |
| `MUSICMASTER_SEEDVC_DIR` | `seedvc_dir` | seed-vc 源码目录 |
| `MUSICMASTER_SVC_PYTHON` | `svc_python` | .venv-svc 的 python.exe |
| `MUSICMASTER_SEP_MODELS` | — | 分离权重缓存目录(默认 `C:\tmp\audio-separator-models`) |
| `LILYPOND_EXE` | — | LilyPond 可执行(简谱出 PDF 需要;**不放全局 PATH**,DLL 冲突) |

- `paths.local.json` **不入库**(gitignore),模板见 `paths.local.json.example`。
  ⚠️ Windows 路径用**正斜杠 `/`** 或双反斜杠;单反斜杠会让 JSON 解析失败(后端会 stderr 告警)。
- 没装 GPU venv 时,分离/修音换音色页给友好提示,**不影响互转/扒谱**。
- 简谱出 **PDF** 需本机装 LilyPond;没装则只产 `.ly` 源(不报错,报告会注明)。

## 7. 必须知道的坑(前端改后端时易踩)

1. **`core/__init__` 同名陷阱(本仓头号反复 bug)**:`musicmaster/core/__init__.py` 把
   `render`/`transcribe`/`separate`/`correct` 这些**函数**绑成了包属性。所以
   `from musicmaster.core import render` 拿到的是**函数**,`render.render(...)` 会 `AttributeError`。
   **正解**:`from musicmaster.core.render import render`(直接从子模块)或
   `importlib.import_module("musicmaster.core.render")`。`vocal/__init__` 同理(`voice` 等)。
2. **改代码要重启 GUI**(模块缓存)。
3. **GBK 控制台**:打印含中文/emoji 要先 `reconfigure("utf-8")`;子进程要带 `PYTHONUTF8=1`/`PYTHONIOENCODING=utf-8`。
4. **Radio 用 `(label, value)` 元组**:显示带括号解释、值是裸名(`crepe`/`dereverb`…)。后端只认裸名,改 label 不影响后端。
5. **修音换音色是慢操作**:整首×高步数在 8GB 上可 20+ 分钟;前端应有进度/耐心提示,别让用户以为卡死。

## 9. 给「重做前端」的人:最小心智模型

> 你不需要懂修音/扒谱算法,只要记住:**前端 = 收集输入 → 调 §4 的某个入口 → 把返回/产物展示出来**。

- 互转 / 扒谱:**同步函数**,直接调、直接拿结果(扒谱产物在 out_dir,读 `报告.md` + 列文件即可)。
- 分离 / 修音换音色:**慢、要 GPU**,前端要有「进行中/进度」态;分离走子进程看 returncode,修音换音色调 `two_stage` 看返回 dict。
- 所有入口**已做兜底**:catch 异常 → 结构化提示,别把 traceback 丢给用户。
- 用户选模型/参数:把 §3 的表做成可展开「帮助」,默认值(crepe / dereverb / 150 / 50 / 0.7)对绝大多数人最优。
